# Joe Sterett

**Technology & product leader building AI systems that turn messy real-world problems into trustworthy operational software.**

I've spent my career working where technology, operations, people, and business problems collide. I'm especially interested in what changes when AI makes it possible to move much faster from **problem discovery → product decision → working software → real-world validation**.

Right now, I'm building **[JoPilot](https://github.com/joesterett1/jopilot)** — an evidence-driven personal intelligence system designed to observe the normal evidence generated by life and work, maintain trustworthy state across it, and surface the right context when that context becomes useful.

## What I'm exploring

- **AI-native product development** — using AI coding agents without outsourcing product judgment, architecture, testing, or responsibility.
- **Trustworthy agentic systems** — provenance, uncertainty, correction, human judgment, bounded action, and safe failure.
- **From messy operations to software** — finding the real problem before automating it.
- **Human-centered automation** — reducing cognitive and administrative burden without creating another system the human has to maintain.

## Featured project

### [JoPilot — Patient 0](https://github.com/joesterett1/jopilot)

JoPilot began with a practical question:

> **What if the system carried the remembering, searching, reconciling, and administrative burden — while the human kept the judgment?**

The project is now being tested against real workflows using forward-only production canaries, provenance-aware evidence, append-only corrections, human-in-the-loop review, and deliberately bounded activation of increasingly consequential capabilities.

A few principles emerging from the work:

> **JoPilot should carry the problem until it reaches the smallest irreducible piece that requires me.**

> **The architecture should become more sophisticated so the interface can become less sophisticated.**

> **Correct what the evidence proves. Preserve what you don't know.**

The public repository is a sanitized architecture and product showcase. Private Patient 0 data and production implementation remain private.

## How I build

I'm not a career software engineer, and I'm not trying to pretend to be one.

My background is technology leadership, product thinking, project/program delivery, systems integration, operations, and translating business problems into working systems. AI has given me a new way to cross the boundary from **defining what should be built** to participating deeply in **how it gets built and validated**.

That means working with AI coding agents while still owning:

- the problem definition;
- architecture and system boundaries;
- acceptance criteria;
- product and UX decisions;
- failure analysis;
- production validation; and
- the decision about what **not** to automate.

I'm documenting that learning in public as I go.
